## 2026-11-04 | 串口首联排查 | 结论：当前为硬件环回，TX/RX 被短接，需重新对线
- 现象：COM4(CH340 重插后由 COM3 变更为 COM4) 链路通，但发送特征字节
  55 AA 00 41 0D 得到 100% 逐字节原样回显——真实控制台不会回显 0x00 等控制字节，
  判定为 TX 与 RX 物理短接（环回），板端控制台未真正接通。
- 基线静默（0 字节/4s）+ 无 U-Boot 提示符 → 板子日志未到达串口。
- 排查步骤（现场执行）：
  1. 断电，检查 J14：USB-TTL 的 **RXD 必须接板 TX0**、**TXD 接板 RX0**（名字交叉），GND-GND；
  2. 确认两根信号线插在**不同**排针孔，无相邻短路/焊桥；
  3. 重新上电后复测特征字节：不再逐字节镜像、敲回车出 `#`/`>` 提示符即通。
- 工具备忘：COM 口号在 USB 重插后会漂移（COM3→COM4），脚本已支持自动扫描。

## 2026-11-09 | 原理图复核纠错 + I2C0根因修复 + 时钟插桩清理

### 一、原理图结论修订（重要）
- 之前“TP9950 输出 DVP 给 T23”的描述**不准确**。
- 逐项复核 `原理图_1-JKD-621-T23-V1.0 原理图_2026-07-22.pdf`：
  - TP9950 SCL/SDA → T23 PA13/PA12，即 **I2C0**，7bit 地址 **0x44**（不是 0x37）。
  - TP9950 RSTB → T23 PA18。
  - TP9950 本地 27MHz 晶振，不依赖 T23 DVP_MCLK。
  - TP9950 到 T23 实际连接 3 对差分线：MIPI CLK + data lane0 + lane1，为 **MIPI CSI-2 2-lane**。
  - TP9950 并行 `VD1_x` 引脚未作为本板数据总线使用。
- `tp9950.c` 已配置 `TX_SENSOR_DATA_INTERFACE_MIPI`、`lans=2`，驱动与原理图一致；文档链路已修订。

### 二、I2C0 无 ACK 根因（比“时钟防御误伤”更直接）

### 二、用户空间寄存器实测
- 直接连续读会发生 `ADDR_NOACK`。
- 每次先写 `reg0x40=0x00` 选择 decoder page，等待后再读，则可靠：
```text
0x40=0x00 → read 0x03 = 0x01
0x40=0x00 → read 0x04 = 0x59
0x40=0x00 → read 0x01 = 0x2c
0x40=0x00 → read 0xfe = 0x00
0x40=0x00 → read 0xff = 0x00
```
- 结论：地址 0x30 正确；该器件对读前 page/间隔有特殊要求；`0xfe/0xff` 不是参考驱动预期的 0x28/0x50(60)。
