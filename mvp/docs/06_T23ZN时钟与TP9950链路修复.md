# T23ZN 时钟与 TP9950 链路修复记录（2026-11-09）

> 结论先行：**本轮 “i2c0 skip clk init” 不是 CGU 时钟防御误伤 I2C0，而是内核配置仍选择 “Using uboot configuration”。我们的救援 U-Boot 没有做 I2C0 PA12/PA13 复用和控制器初始化，驱动按官方假设跳过初始化，导致 TP9950 无 ACK。**

## 1. 原理图复核后的正确视频链路

此前文档把 TP9950 输出写成 DVP。重新按 `原理图_1-JKD-621-T23-V1.0 原理图_2026-07-22.pdf` 逐项核对后，应修订为：

```text
4 路 AHD 摄像头
  → J12/J13/J3/J2 与前端匹配/保护/供电开关
  → TP9950 4 路 AHD 输入 VIN1~VIN4
  → TP9950 单解码内核 + 通道选择
  → TP9950 MIPI CSI-2 2-lane 输出
  → T23 共享 DVP/MIPI 引脚（MIPI 模式）
  → T23 ISP / 编码
```

TP9950 并行脚 `VD1_x` 在本板未作为对外数据总线使用；原理图实际连接的是 3 对差分线：CLK、lane0、lane1。

### 1.1 TP9950 控制 / 复位

| TP9950 引脚 | 网络名 | T23 侧 | 说明 |
|---|---|---|---|
| SCL | `SMB0_SCK_PA13` | T23 PA13 / I2C0-SCL | 100 kHz 起步 |
| SDA | `SMB0_SDA_PA12` | T23 PA12 / I2C0-SDA | 7bit 地址 `0x44` |
| RSTB | `MSC1_D3_PA18` | T23 PA18 | 驱动内复位 GPIO，高电平释放 |
| XTI/XTO | 27 MHz 晶振 | 无 T23 MCLK 依赖 | TP9950 本地时钟 |

注意：T23 `DVP_MCLK_PA15` 不是本链路必备时钟。

### 1.2 MIPI CSI-2 映射

| TP9950 | T23 网络名 | T23 引脚 |
|---|---|---|
| `CKP/CLKO` | `DVP_D2_MIPI_CLKP` | 26 |
| `CKN` | `DVP_D3_MIPI_CLKN` | 25 |
| `D0P` | `DVP_D4_MIPI_DATAP0` | 24 |
| `D0N` | `DVP_D5_MIPI_DATAN0` | 23 |
| `D1P` | `DVP_D0_MIPI_DATAP1` | 29 |
| `D1N` | `DVP_D1_MIPI_DATAN1` | 28 |

`tp9950.c` 中 `dbus_type = TX_SENSOR_DATA_INTERFACE_MIPI`、`lans = 2`，与原理图一致。

### 1.3 四路 AHD 输入

| 连接器 | TP9950 输入 | 原理图位置 |
|---|---|---|
| J12 | `VIN1/VIN1P`、`VIN2/VIN1N` | 左上 |
| J13 | 同一差分输入域第二路 | 左下 |
| J3 | `VIN3/VIN2P`、`VIN4/VIN2N` | 右上 |
| J2 | 同一差分输入域第四路 | 右下 |

TP9950 仍为单解码内核，四路只能软件轮询选通，不能四路同时并发采集。

## 2. 本轮发现的配置冲突

### 2.1 I2C0 不能选 BOOT_DEFAULT

旧配置：

```text
CONFIG_I2C0_V12_JZ=y
# CONFIG_I2C0_PA12_PA13 is not set
CONFIG_I2C0_BOOT_DEFAULT=y
```

`i2c-v12-jz.c` 在 `CONFIG_I2C0_BOOT_DEFAULT` 下会跳过 PA12/PA13 复用、`clk_enable()`、设速和控制器初始化。官方 Zeratul 链路假设 U-Boot 已完成这些动作；当前 SD rescue U-Boot 没做，因此出现 `i2c0 skip clk init`。

修复为：

```text
CONFIG_I2C0_V12_JZ=y
CONFIG_I2C0_PA12_PA13=y
# CONFIG_I2C0_BOOT_DEFAULT is not set
CONFIG_I2C0_SPEED=100
```

### 2.2 I2C1 会抢占 MIPI 复用域

旧配置 `CONFIG_I2C1_PA16_PA17=y` 会把 PA16/PA17 复用成 I2C1。本板没有 I2C1 外设，且这对脚位于 T23 MIPI/DVP 共享域，保留会干扰后续 MIPI 接收。修复为：

```text
# CONFIG_I2C1_V12_JZ is not set
```

### 2.3 VFAT 必须内置

最小 rootfs 没有 `fat.ko/vfat.ko`，旧内核虽识别 `mmcblk0p1`，但 `mount -t vfat` 报 `No such device`。MVP 需要从 TF 加载驱动和缓存图片，因此：

```text
CONFIG_FAT_FS=y
CONFIG_VFAT_FS=y
```

## 3. T23ZN 时钟防御收敛

保留：

1. `clk_cgu.c`：拦截 `CGU_SSI` 的 rate/parent/init 访问。
2. `clk.c`：跳过 `CLK_ID_SSI0` gate 初始化。
3. `clk_sources.c`：SSI0 父时钟改为安全 `EXT1`。
4. `clk_cgu.c`：CGU busy 等待增加有限超时。

移除全部临时阶段标记与 `+pr|pr`、`R8P`、`CGU-TO` 串口噪声。当前源码已无 `prom_putstr` 插桩。

## 5. 上电验收

1. TF 卡插板，J16 短接（BOOT_SEL0 选择 SD/TF 启动）。
2. USB-TTL 接 J14：USB-RXD ← 板 TXD(PB23)，USB-TXD → 板 RXD(PB24)，GND 共地。
3. 串口 115200-8N1，无流控。
4. 断电 3 秒后上电。

必须看到：

```text
i2c i2c-0: set:... dev=... ...
i2c i2c-0: i2c0 register ok.
```

不应再出现 `i2c-1`。

Shell 验证：

```bash
mkdir -p /mmc
mount -t vfat /dev/mmcblk0p1 /mmc
ls /mmc
/mmc/i2cscan 0
```

预期 TP9950 在 `0x44` ACK。

## 6. 无 ACK 排障顺序

1. 万用表确认 TP9950 SCL/SDA 静态约 3.3V。
2. 确认摄像头模组接在 J12/J13/J3/J2 之一且 TP9950 供电正常。
3. 重新拉高-拉低-拉高 PA18 后再扫 `0x44`。
4. 降到 50 kHz 或暂切 soft-I2C，区分控制器问题与上拉/负载问题。
5. soft-I2C 也无 ACK 时查焊接、上拉、供电、RSTB。

## 7. ACK 后恢复 ISP

当前内核为了先验证 I2C/TF，暂时 `CONFIG_VIDEO_TX_ISP=n`，不能出图。ACK 后恢复：

```text
CONFIG_VIDEO_TX_ISP=y
CONFIG_TX_ISP_CORE=y
CONFIG_BUILT_IN_SENSOR_SETTING=y
```

此前 `AE_TABLE_ADDR` / `iq_data_proc_fops` 编译失败的实际原因是 `BUILT_IN_SENSOR_SETTING` 曾被 olddefconfig 随 `VIDEO_TX_ISP` 一起清掉；三开关同时恢复后无需 stub。
